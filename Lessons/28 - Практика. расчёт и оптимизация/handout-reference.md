## 0. Договорённости — читать до начала

1. **Считаем порядок величины, а не бухгалтерию.** Округляем до одной-двух значащих цифр. `$372 600` → «≈ $370k». Точность ±50% — норма, ошибка в 10 раз — нет.
2. **Пишем формулу, а не только результат.** Число без формулы не принимается: проверить нельзя, повторить нельзя.
3. **Каждое допущение — вслух и в лист.** «Средний объект 300 КБ», «утилизация инстанса 70%». Допущение можно оспорить, молчаливую подстановку — нет.
4. **Цены условные и провайдер-агностик.** У AWS / GCP / Yandex Cloud цифры отличаются, структура счёта — нет. Мы тренируем метод, а не тариф.
5. **Единицы:** 1 ТБ = 1000 ГБ, 1 ПБ = 1000 ТБ. Платим всегда за **гигабайты**.
6. **Биты ≠ байты.** Битрейт в Мбит/с, объём в МБ. Делить на 8. Это ошибка №1 на видео-расчётах.

## 1. Юнит-цены (условные, $)

### Compute

| Ресурс | Цена | Примечание |
|---|---|---|
| vCPU | **$0.04 / час** ≈ **$30 / месяц** | 1 месяц = 730 часов |
| Инстанс 4 vCPU / 16 ГБ | **$0.16 / час** ≈ **$120 / месяц** | базовая «рабочая лошадка» |
| Инстанс 8 vCPU / 32 ГБ | **$0.32 / час** ≈ **$240 / месяц** | |
| Reserved (1–3 года) | **−50%** | только на стабильную базу |
| Spot / preemptible | **−80%** | только stateless и прерываемое |

### Storage

| Тип | Цена | Когда |
|---|---|---|
| Объектное **hot** | **$0.023 / ГБ-мес** ≈ **$23 / ТБ-мес** | активные данные |
| Объектное **cold / архив** | **$0.004 / ГБ-мес** ≈ **$4 / ТБ-мес** | + плата за извлечение |
| Блочный **SSD** (под БД) | **$0.10 / ГБ-мес** ≈ **$100 / ТБ-мес** | самый дорогой тир |

### Network

| Направление | Цена |
|---|---|
| **Ingress** (внутрь облака) | **$0** |
| **Egress** наружу с origin | **$0.08 / ГБ** |
| **Egress через CDN** | **$0.03 / ГБ** (медиа на объёме — до **$0.02**) |
| **Cross-AZ** (между зонами) | **$0.01 / ГБ в каждую сторону** |

### Managed

| Что | Цена |
|---|---|
| Managed БД / кэш / очередь | **×2 к стоимости** эквивалентного self-hosted (compute + диск) |
| Балансировщик | ≈ **$25 / мес** + **$0.008 / ГБ** обработанного трафика |

## 2. Инженерные константы (чтобы не спорить)

| Величина | Берём | Комментарий |
|---|---|---|
| Один инстанс 4 vCPU держит | **~1 000 RPS** простых API-запросов | тяжёлые запросы с БД — в 5–10 раз меньше |
| Целевая утилизация инстанса | **60–70%** | 100% не закладывают никогда |
| Запас на отказ и деплой | **×2** к расчётному числу инстансов | N+1, multi-AZ, rolling update |
| Накладные расходы БД | **×2–3** к объёму сырых данных | индексы, WAL, реплики, бэкапы |
| Средний размер API-ответа | **1–5 КБ** | JSON без медиа |
| Cache-hit ratio CDN на популярном медиа | **90–95%** | «длинный хвост» — заметно ниже |

**Битрейт → объём:**
```
ГБ за час = битрейт_Мбит/с × 3600 / 8 / 1000
3 Мбит/с → 1.35 ГБ/час      5 Мбит/с → 2.25 ГБ/час      8 Мбит/с → 3.6 ГБ/час
```

**Доступность → простой:**

| SLA | В год | В месяц |
|---|---|---|
| 99% | 3.65 дня | 7.2 часа |
| 99.9% | 8.8 часа | 43 минуты |
| 99.99% | 53 минуты | 4.4 минуты |

## 3. Конвейер расчёта — шесть шагов

```
   ①  СЦЕНАРИИ            DAU × действий на пользователя × fan-out
        │                 = запросов в сутки
        ▼
   ②  RPS                 среднее = запросов / 86 400
        │                 пик     = среднее × Peak Factor
        │                 отдельно ЧТЕНИЕ и ЗАПИСЬ
        ▼
   ③  ОБЪЁМЫ              storage = записей/сутки × размер × дни × накладные
        │                 bandwidth = отдач × средний объект
        ▼
   ④  РЕСУРСЫ             инстансы = пик RPS / RPS_на_инстанс × запас
        │                 БД: ноды, диск, IOPS
        ▼
   ⑤  ДЕНЬГИ              × юнит-цены → счёт по 4 осям
        │                 compute / storage / network / managed
        │                 → ГДЕ 80% ДЕНЕГ?
        ▼
   ⑥  ОПТИМИЗАЦИЯ         бьём по самой большой статье
                          каждая экономия: чем платим?
```

> **Правило порядка:** начинай счёт **с трафика**, а не с серверов. Для read-heavy и медиа сеть обычно доминирует, а её легче всего пропустить.

## 4. Типовые ошибки — проверь себя перед сдачей

| # | Ошибка | Как ловить |
|---|---|---|
| 1 | Забыт **egress** | Есть ли в счёте строка «network»? Если нет — счёт неполный |
| 2 | Посчитано **по среднему**, забыт Peak Factor | Система живёт в пике, а не в среднем |
| 3 | Обратное: **весь парк отсайзен по пику 24/7** | Платим за пик круглосуточно, хотя он 2 часа в день |
| 4 | **Биты vs байты** | Мбит/с → МБ/с делить на 8 |
| 5 | Забыт **fan-out**: один экран = 5–10 запросов | «Пользователь открыл ленту» ≠ 1 RPS |
| 6 | Объём хранилища **без индексов, реплик и бэкапов** | ×2–3 к сырым данным |
| 7 | Хранилище посчитано **не накопительно** | За год — это сумма за 365 дней, а не объём одного дня |
| 8 | **100% утилизация** инстанса | Закладывай 60–70% |
| 9 | Точность до цента при неизвестности ±50% | Округляй |
| 10 | **Cost/DAU не сверен с ARPU** | Если инфраструктура на юзера дороже, чем он приносит — бизнес убыточен на железе |
| 11 | Оптимизируется **не та статья** | Экономия $200 из счёта в $370 000 — это не оптимизация |

## 5. Глоссарий — если термин встретился впервые

Здесь всё, что может попасться в вашей карточке, в разборе соседней команды и в итогах занятия. Смотреть по мере надобности, читать целиком не нужно.

**Про нагрузку**

- **MAU / DAU** — уникальных пользователей за месяц / за день. Расчёт нагрузки почти всегда ведут от DAU.
- **RPS** — запросов в секунду.
- **Fan-out** — сколько запросов к серверу порождает одно действие пользователя. Открыл экран — ушло 3–10 запросов.
- **Peak Factor** — во сколько раз пик выше среднего.
- **Утилизация** — какая доля купленных мощностей реально работает.
- **p95 / p99** — «95 (99) случаев из 100 быстрее чем». Среднее в требованиях к скорости не используют: оно прячет как раз те случаи, из-за которых жалуются.

**Про данные и трафик**

- **Egress / трафик наружу** — данные, которые вы отдаёте пользователю. Платные. Загрузка в облако (ingress) обычно бесплатна.
- **CDN** — сеть серверов по миру, кэширующая контент ближе к пользователю. Дешевле за гигабайт и быстрее.
- **Битрейт** — сколько данных в секунду весит видео. В **битах**; для байтов делить на 8.
- **Hot / cold storage** — быстрое дорогое хранилище / медленное дешёвое (архив).
- **TTL** — срок жизни данных, после которого они удаляются или уезжают в архив.
- **Накладные расходы БД** — индексы, журнал транзакций (WAL), реплика, бэкапы. Реальный объём в 2–3 раза больше «сырых» данных.

**Про способ доставки данных**

- **Polling (опрос)** — клиент сам регулярно спрашивает сервер «что нового?». Просто, но каждый вопрос стоит запроса, даже когда новостей нет.
- **Push (WebSocket, SSE)** — наоборот: соединение держится открытым, и сервер сам сообщает клиенту об изменении. Дешевле по запросам и быстрее, но соединения надо обслуживать.

**Про инфраструктуру**

- **Инстанс / нода** — одна работающая машина (виртуальная или контейнер).
- **Managed-сервис** — база, кэш или очередь, которые обслуживает провайдер. Примерно вдвое дороже, зато без ночных дежурств.
- **Stateless** — сервис, не хранящий состояние между запросами. Такой можно свободно останавливать и размножать.
- **Autoscaling** — автоматическое добавление мощностей при росте нагрузки. Реагирует не мгновенно: обычно 1–3 минуты.
- **Spot / preemptible** — дешёвый тариф с условием, что машину могут забрать в любой момент.
- **Шардирование** — разделение данных на независимые части, чтобы нагрузка не упиралась в одну точку.
- **Консистентность** — гарантия, что данные не разъедутся. Например: одно место не может быть продано дважды.
- **Идемпотентность** — свойство операции давать тот же результат при повторе. Важно там, где запрос могут отправить дважды.

## 6. Формат результата (он же — шаблон сдачи ДЗ)

| Раздел | Что должно быть |
|---|---|
| **Допущения** | Список того, что вы подставили от себя |
| **RPS** | Чтение и запись, среднее и пик, с формулами |
| **Хранилище** | На 1 год и на 3 года, с учётом накладных |
| **Bandwidth** | Egress в месяц + пиковая полоса (Гбит/с) |
| **Ресурсы** | Инстансы, ноды БД, диски — таблицей |
| **Счёт** | По 4 осям + доля каждой + **cost/DAU** |
| **Узкое место** | Одно, главное, с обоснованием почему именно оно |
| **Оптимизации** | 3–5 штук: что делаем / сколько экономим / **чем платим** |

> Пункт «**чем платим**» обязателен. Оптимизация без указания цены — это не оптимизация, а пожелание.
