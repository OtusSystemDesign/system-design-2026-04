# Команда A — «Лекторий»

> Всё, что нужно для расчёта, есть в этой карточке и в справочнике `handout-reference.md`.
> Гуглить тарифы и характеристики не нужно. Считаем **порядок величины**, не бухгалтерию.

---

## Что это за система

Образовательная видеоплатформа. Люди заходят с телефона или из браузера и смотрят лекции: выбирают курс, включают видео, смотрят в среднем час в день. Плеер сам подстраивает качество под скорость интернета. Если человек ушёл на середине лекции — в следующий раз она продолжится с того же места.

Внутри это выглядит так: есть **каталог** (поиск, страницы курсов — обычные запросы к API), есть **видеофайлы** (лежат в хранилище, отдаются в плеер), и есть **прогресс просмотра** (плеер регулярно сообщает серверу, на какой секунде находится зритель).

---

## Ваша задача

Посчитать, **сколько эта система стоит в месяц**, найти **где сосредоточены деньги**, и предложить, **что с этим делать**.

---

## 🔍 На что смотреть именно в этой системе

Три вещи, которые отличают «Лекторий» от других систем. Держите их в голове весь расчёт:

1. **Пользователь не только отправляет запросы — он получает много данных.** Один клик «play» — это один запрос, но следом за ним течёт час видео. Считайте оба потока, они измеряются в разном.
2. **Каталог большой, но смотрят не всё одинаково.** Свежий популярный курс и лекция трёхлетней давности лежат в одном хранилище, но живут по-разному.
3. **Вечером людей в разы больше, чем в среднем по суткам.** Система должна выдерживать вечер, а не «среднюю температуру».

## Вводные

### Аудитория

| Параметр | Значение | Что это значит |
|---|---|---|
| MAU | 4 000 000 | Уникальных пользователей за месяц. Для расчёта нагрузки почти не нужен — берите DAU |
| **DAU** | **400 000** | Активных **в день**. Это база всех расчётов |
| Просмотр на человека в день | **1 час** | В среднем. Кто-то смотрит 3 часа, кто-то 10 минут |
| **Пик** | **×2.5** | Вечером (19:00–23:00) одновременных зрителей в 2.5 раза больше среднего |
| Средний битрейт | **3 Мбит/с** | Сколько данных в секунду «весит» видео. Это **биты**, не байты |

### Контент

| Параметр | Значение | Что это значит |
|---|---|---|
| Каталог | **20 000 часов** | Общая длительность всех лекций |
| Качеств на видео | 4 | 1080p / 720p / 480p / 360p — один и тот же ролик хранится в четырёх версиях |
| Вес одного часа во всех качествах | **~2.5 ГБ** | Уже с учётом всех четырёх версий |
| Прирост | **3 000 часов в год** | Записывают новые курсы |
| Доля каталога, дающая 80% просмотров | **~15%** | Остальное смотрят редко |

### Как устроено воспроизведение

| Параметр | Значение | Что это значит |
|---|---|---|
| Heartbeat плеера | **раз в 30 секунд** | Плеер сообщает серверу текущую секунду просмотра. Это **запись** в базу |
| Навигация, поиск, страница курса | обычные API-запросы | Считайте примерно 1 600 запросов/с в вечерний пик |

### Требования к качеству (НФТ)

| Требование | Значение | Простыми словами |
|---|---|---|
| Старт воспроизведения | p95 ≤ 2 с | 95 зрителей из 100 видят картинку быстрее чем за 2 секунды |
| Ребуферизация | ≤ 1% времени | Видео «крутит колёсико» не больше 1% времени просмотра |
| Доступность | 99.9% | Допустимо ~44 минуты недоступности в месяц |
| Восстановление после сбоя | RTO ≤ 30 мин, RPO ≤ 5 мин | За сколько поднимаемся и сколько данных готовы потерять. Прогресс просмотра — не критичные данные |
| Хранение | бессрочно | Архив курсов не удаляем |

## Что сделать

Шесть шагов. Формулы уже написаны — подставьте числа. Записывайте прямо сюда.

### Шаг 1. Сколько запросов в секунду

```
Часов просмотра в сутки  = DAU × часов на человека
                         = ________ × ____ = ____________

Одновременных зрителей   = часов просмотра в сутки / 24
(среднее)                = ____________ / 24 = __________

Одновременных зрителей   = среднее × Peak Factor
(ПИК, вечер)             = __________ × 2.5 = __________

RPS от heartbeat (пик)   = одновременных зрителей в пик / 30 секунд
                         = __________ / 30 = __________

RPS навигации (пик)      = 1 600 (дано)
─────────────────────────────────────────────────────────
ИТОГО чтение, пик        = __________
ИТОГО запись, пик        = __________     ← подумайте, куда отнести heartbeat
```

### Шаг 2. Сколько трафика уходит пользователям

> Это ключевой шаг для вашей системы. Не торопитесь.

```
ГБ за час видео  = битрейт (Мбит/с) × 3600 / 8 / 1000
                 = 3 × 3600 / 8 / 1000 = ______ ГБ

Трафик в сутки   = часов просмотра в сутки × ГБ за час
                 = ____________ × ______ = ____________ ГБ = ______ ТБ

Трафик в месяц   = трафик в сутки × 30
                 = ____________ = ______ ТБ = ______ ПБ

Пиковая полоса   = одновременных зрителей в пик × битрейт
                 = __________ × 3 Мбит/с = __________ Мбит/с = _____ Гбит/с
```

### Шаг 3. Сколько места занимают видео

```
Каталог сейчас   = 20 000 часов × 2.5 ГБ = ________ ГБ = ______ ТБ
Прирост за год   = 3 000 часов × 2.5 ГБ  = ________ ТБ

Через 1 год: ______ ТБ          Через 3 года: ______ ТБ

Разделите на два тира (см. подсказку «на что смотреть», пункт 2):
   горячее (~20%): ______ ТБ × $23/ТБ-мес = $______
   архив   (~80%): ______ ТБ × $4/ТБ-мес  = $______
```

### Шаг 4. Сколько нужно серверов

```
Серверов = RPS в пике / 1 000 на сервер × 2 (запас на отказ и деплой)
         = __________ / 1000 × 2 = ______ серверов

Стоимость = ______ × $120/мес = $__________

Плюс transcoding (перекодирование новых лекций в 4 качества): считайте ~$40/мес
Плюс managed (база метаданных, кэш, очередь): считайте ~$1 500/мес
```

### Шаг 5. Счёт — и главное, раскладка

Посчитайте трафик в **двух вариантах**: как есть (раздаём видео напрямую со своих серверов) и через CDN.

```
Вариант «напрямую»: ____________ ГБ × $0.08/ГБ = $____________

Вариант «через CDN» (CDN забирает 95% трафика на себя):
   свои серверы: ____________ ГБ × 5%  × $0.08 = $__________
   CDN:          ____________ ГБ × 95% × $0.02 = $__________
                                        итого  = $__________
```

| Ось | $/мес | Доля от итога |
|---|---|---|
| **Network** (трафик) | | **____%** |
| **Compute** (серверы) | | ____% |
| **Storage** (хранилище) | | ____% |
| **Managed** (БД, кэш) | | ____% |
| **ИТОГО** | | 100% |

```
Стоимость одного пользователя = ИТОГО / DAU = $__________ в месяц
```

> **Проверьте себя.** Подписка на такой сервис стоит примерно $6 в месяц, платит примерно каждый шестой активный пользователь. Сходится ли экономика?

### Шаг 6. Узкое место и оптимизации

> **Если не знаете, с чего начать — ответьте по порядку на четыре вопроса.**

## Если закончили раньше времени

Не сидите — возьмите любой вопрос, ответ пойдёт в защиту как бонус.

1. **Рост.** Что будет со счётом, если DAU вырастет в 5 раз? Все ли статьи вырастут одинаково?
2. **Отказ.** CDN внезапно недоступен в вечерний пик. Какая полоса понадобится вашим серверам и что произойдёт?
3. **Экономика.** При какой доле платящих подписчиков сервис выходит в ноль по инфраструктуре?
4. **Спор с константой.** Мы взяли «1 000 запросов в секунду на сервер». От чего эта цифра зависит на самом деле, **откуда взять достоверное значение** вместо нашего и как изменится ответ, если оно втрое меньше?

## Мини-глоссарий

- **DAU** — активных пользователей в день.
- **RPS** — запросов в секунду.
- **Peak Factor** — во сколько раз пик выше среднего.
- **Egress / трафик наружу** — данные, которые вы отдаёте пользователю. Платные. Загрузка данных в облако обычно бесплатна.
- **CDN** — сеть серверов по всему миру, которая кэширует ваш контент ближе к пользователю. Дешевле за гигабайт и быстрее.
- **Битрейт** — сколько данных в секунду весит видео. В **битах**; чтобы получить байты, делим на 8.
- **p95** — «95 случаев из 100 быстрее чем». Среднее в таких требованиях не используют: оно прячет самые плохие случаи.
- **Managed-сервис** — база или кэш, которые обслуживает провайдер, а не вы. Дороже примерно вдвое, зато без ночных дежурств.
